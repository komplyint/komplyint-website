## Public copy direction

Lead with **problem → practical response → target outcome**. Four visible challenge stories:

1. Legacy or difficult-to-maintain application → investigate existing code and implement scoped fixes → easier ongoing development.
2. Broken or fragile system interfaces → implement/test APIs and error handling → more reliable data flow.
3. Backlogged features → contribute defined frontend/backend tasks to the customer's agile process → move priority work forward.
4. Release and regression risk → functional QA, reproducible bug reports, API/browser tests and suitable automation → clearer quality evidence.

Place agile collaboration below these challenge stories: understand current state and acceptance criteria, deliver in increments, test and hand over. Treat `ketterä` as a **way of working**; do not claim Scrum Master certification or a specific sprint velocity.

Technology names (TypeScript, JavaScript, React, Angular, Vue, Node.js, C#/.NET, APIs, Kafka, Docker, Azure Functions) support the technical qualification conversation but are not the headline. The specialist's previous employment projects must not be shown as Komplyint Oy case studies.

## Who performs what

- **Project-based full-stack specialist:** software and website engineering in **English** after assignment-specific availability and contract checks. Finnish-speaking customer coordination may be agreed separately. No blanket Finnish-speaking developer claim.
- **Komplyint owner:** data, Power BI, Microsoft 365 support, functional QA, project tracking, documentation and customer coordination in **Finnish and English**. The owner has familiarity with HTML/CSS/JavaScript, but this is **not represented as professional web-development experience**.
- **Swedish:** only a publication language for website and brochures; do not imply Swedish-language delivery.

## Quality and sales constraints

No fabricated client case, percentage improvement, benchmark, specific delivery time, 24/7 availability, security clearance or compliance certification. Projects and staffing are subject to explicit feasibility, scope, approved specialist, client requirements and acceptance criteria.

Public research examples remain exclusively in this **internal marketing evidence note**, not the company's public customer-reference gallery.
